Бот для поиска и автоотклика на вакансии на российских job-площадках, плюс поиск и опциональные автосообщения контактам в Telegram-каналах.

## Что нового (2026-08-27)

- Telegram — больше не только поиск: если в посте канала нашёлся ровно один `@username`-контакт, бот может сам написать ему короткое приветствие (`telegram.auto_message`), с человекоподобной паузой (2-10 минут), дневным лимитом и окном активных часов — не всё сопроводительное письмо целиком, чтобы не выглядеть рассылкой. Дальнейшая переписка — в новой вкладке дашборда **"Telegram" → "Диалоги"** (история сообщений по контакту, бейдж непрочитанных, ручной ответ прямо из дашборда); автоответа на входящие нет и не планируется. Посты старше `telegram.max_post_age_days` (по умолчанию 7) не рассматриваются вообще, а каналы можно указывать и полной ссылкой (`https://t.me/...`), не только username.
- Дашборд: отдельная вкладка "Telegram" (каналы, свежесть постов, автосообщения, диалоги) вынесена из общей панели "Поиск" — площадки и Telegram теперь разные разделы UI.
- Позиции/локации теперь можно переопределить для одной конкретной площадки (включая Telegram), не трогая общий список — пусто у площадки означает "используй общий" (см. `effective_list` в GUIDE.md).
- HeadHunter: обрабатывается ещё один вариант анкеты при отклике — отдельная страница `/applicant/vacancy_response` (раньше распознавалась только модалка на той же странице).
- Уведомление, если за весь прогон ни один вызов LLM не прошёл успешно (похоже на исчерпанный бесплатный лимит провайдера) — вакансии в этом случае оцениваются через fallback, без реальной LLM-проверки.
- Дашборд: кнопка "🎲 Распределить по площадкам" — раскидывает общий дневной лимит откликов по включённым в расписание площадкам случайными долями (LinkedIn — вдвое меньше остальных) одним кликом; отдельная панель "Ожидания по зарплате" (рубли/месяц для HH, доллары/год для LinkedIn — разные поля под разные рынки).

## Что делает

- Ищет вакансии по вашим критериям (`work_preferences.yaml`) на подключённых площадках, включая Telegram-каналы.
- Пишет персональное сопроводительное письмо под каждую вакансию с помощью LLM, на основе вашего PDF-резюме (`data_folder/resume.pdf`) — само резюме не переписывается.
- Откликается автоматически (или в режиме dry-run, без реальной отправки) и ведёт историю откликов — включая читаемый HTML-отчёт (`data_folder/output/applications.html`) со статистикой за день/неделю/месяц и таблицей с зарплатой и сайтом компании (где площадка их публикует), чтобы всегда было видно, кому и что отправлено, когда придёт ответ. Историю можно экспортировать в TXT или PDF через пункт меню "Export application history".
- В Telegram-каналах, где нет кнопки "откликнуться" — опционально пишет первым найденному в посте контакту (короткое приветствие, не всё письмо) и ведёт с ним переписку в отдельном разделе дашборда — см. "Что нового" выше.
- Защищается от бана аккаунта: случайная пауза 30-90с между реальными откликами (2-10 минут — между холодными сообщениями в Telegram), суточный лимит откликов на площадку (`DAILY_APPLICATION_LIMIT`) плюс опциональный общий лимит на все площадки сразу, опциональный `apply_once_at_company` (не откликаться в одну компанию дважды).
- Перед письмом/откликом LLM оценивает соответствие резюме вакансии (1-10, порог `JOB_SUITABILITY_SCORE` в `config.py`) — плохо подходящие вакансии пропускаются, не тратя реальный отклик.

## Лимиты и анти-бан

Дневной лимит и лимит за один прогон — это **наши собственные** настройки (пацинг, чтобы не выглядеть ботом), не официальные цифры площадок — они либо нигде публично не задокументированы (HH прямо пишет: превысил — получишь 429, для больших объёмов пишите на api@hh.ru), либо неприменимы (у geekjob/rabota.ru/GetMatch нет официального API вообще, только скрейпинг; у Telegram — это личный аккаунт, а не API-интеграция с лимитами площадки).

Значения ниже — дефолты из `config.py`. Их можно менять на ходу, без перезапуска и правки кода, в дашборде: вкладка **Настройки → Лимиты откликов** — как общие (все площадки сразу, включая отдельный общий дневной лимит `limits.total_daily_application_limit` и кнопку "🎲 Распределить по площадкам"), так и переопределить для одной конкретной площадки (или вручную — блок `limits:`, либо `job_max_applications`/`daily_application_limit` внутри блока нужной площадки в `work_preferences.yaml`). Чем выше значения — тем больше шанс, что площадка распознает автоматизацию; дашборд показывает этот риск прямо рядом с настройкой, но решение — за пользователем.

| Площадка | Дневной лимит откликов | За один прогон | Официальный лимит площадки |
|----------|------------------------|-----------------|------------------------------|
| HeadHunter | `DAILY_APPLICATION_LIMIT` = 15 (±случайные 70-100%) | `JOB_MAX_APPLICATIONS` = 5 | Не задокументирован публично (429 при превышении) |
| SuperJob | 15 (±70-100%) | 5 | Не задокументирован публично |
| zarplata.ru | 15 (±70-100%) | 5 | Не задокументирован (та же платформа, что HH) |
| geekjob.ru | Своего дневного лимита нет — используется `job_max_applications` за прогон | 5 вакансий за прогон | Нет официального API — кулдаун 24ч при признаках капчи/бана (`block_detection.py`) |
| rabota.ru | Своего дневного лимита нет — используется `job_max_applications` за прогон | 5 | Нет официального API — тот же кулдаун |
| GetMatch | Своего дневного лимита нет — используется `job_max_applications` за прогон | 5 | Нет официального API — тот же кулдаун |
| Telegram-каналы | `telegram.daily_message_limit` = 15 холодных сообщений/день (только если включён `auto_message`) | `messages_per_channel` = 100 сообщений на канал за прогон | Личный аккаунт, не API-интеграция — лимитов площадки нет, риск в самом Telegram (ограничение аккаунта за спам) |
| LinkedIn | `LINKEDIN_DAILY_APPLICATION_LIMIT` = 8 (±70-100%) | 5 | Официального API нет — автоматизация против ToS, см. оговорку в [GUIDE.md](docs/GUIDE.md) |

`±70-100%` — это `randomized_daily_limit()`: реальный лимит на день выбирается случайно в этом диапазоне один раз за прогон, чтобы дневной лимит не был идеально одинаковым каждый день (см. [GUIDE.md](docs/GUIDE.md) про анти-бан).

"За один прогон" (`job_max_applications`) — общий лимит на все площадки сразу, меняется одной настройкой в дашборде.

Подробный гайд по настройке (куда класть резюме, как заполнять `secrets.yaml`/`work_preferences.yaml`, что делает бот на каждом шаге) — [docs/GUIDE.md](docs/GUIDE.md).

## Установка

```bash
pip install -r requirements.txt
python main.py
```

При первом запуске без `data_folder/` бот сам предложит создать его
из шаблона и попросит ключ LLM (Enter — чтобы пропустить и вписать
позже). Остальное (площадки, резюме) — вручную по шагам ниже или по
[docs/GUIDE.md](docs/GUIDE.md). Тот же результат руками:

```bash
cp -r data_folder_example data_folder
# заполните data_folder/secrets.yaml и data_folder/work_preferences.yaml
# положите своё резюме как data_folder/resume.pdf
```

Неинтерактивный запуск (для cron):

```bash
python main.py --auto headhunter   # или --auto superjob / --auto zarplata / --auto geekjob / --auto rabota_ru / --auto telegram / --auto getmatch / --auto linkedin
python main.py --auto check_telegram_replies   # проверка новых ответов в Telegram-диалогах (только уведомление)
```

Вместо внешнего cron можно использовать встроенный планировщик
(`python main.py --daemon`) или десктоп-приложение с веб-дашбордом
(`python desktop_app.py`, требует `pip install -r
requirements-desktop.txt`) — статус площадок, история, ответы
работодателей, диалоги в Telegram и настройки в одном окне вместо
ручной правки YAML. Дашборд умеет и первоначальную настройку с нуля
(свой веб-мастер — не нужен `data_folder/` заранее), и точечные
действия без перезапуска: редактировать должности/локации/чёрные
списки (вкладка Настройки → Поиск) — включая кнопку "Сгенерировать
должности из резюме" (LLM сам предложит 2-4 подходящие должности по
PDF-резюме, без правки work_preferences.yaml вручную), настраивать
Telegram отдельно (вкладка "Telegram" — каналы, автосообщения,
диалоги), распределять дневной лимит откликов по площадкам одной
кнопкой, задавать ожидания по зарплате отдельно для HH и LinkedIn,
пересобрать `plain_text_resume.yaml` из PDF, экспортировать
`applied_log.json` как бэкап, получить уведомление в Telegram, когда
дневные траты на LLM превысят заданный порог (или когда все
провайдеры LLM недоступны), и переключить провайдера/модель LLM
(OpenAI/Groq/Gemini/DeepSeek/NVIDIA NIM/OpenRouter/Ollama) со своим
API-ключом на каждого — без правки `config.py`. Подробности — в
[docs/GUIDE.md](docs/GUIDE.md).

## Конфигурация

- `data_folder/secrets.yaml` — ключ LLM (`llm_api_key`, по умолчанию для OpenAI) и, для каждой площадки, свои ключи (HeadHunter секретов не требует — вход браузерный, по номеру телефона и SMS, см. GUIDE.md; SuperJob — https://api.superjob.ru/register/, Zarplata.ru — тот же принцип, что у HH раньше, Telegram — https://my.telegram.org/apps, см. GUIDE.md). Провайдер LLM не обязан быть OpenAI — поддерживаются Groq/Gemini/DeepSeek/NVIDIA NIM/OpenRouter/Ollama, каждый со своим ключом в блоке `llm_api_keys:` (переключение, выбор модели и ввод ключей — в дашборде, вкладка Настройки, без правки `config.py`). **Рекомендация по умолчанию — Groq, модель `openai/gpt-oss-120b`** (помечена короной 👑 в выборе модели): бесплатно и достаточно для оценки вакансий/писем, при таком объёме вызовов LLM платный провайдер за день накапает заметный счёт.
- `data_folder/work_preferences.yaml` — позиции, локации, чёрные списки компаний/названий/локаций, фильтры по опыту/типу занятости/дате, и опциональные блоки `headhunter:`/`superjob:`/`zarplata:` (`auto_apply`, `resume_id`) и `telegram:` (`channels`, `auto_message`, `daily_message_limit`, `max_post_age_days`, `intro_message_template`). Любую площадку, включая Telegram, можно точечно переопределить своими `positions`/`locations` внутри её блока — пусто там означает "используй общий список сверху".
- `data_folder/resume.pdf` — резюме как есть; используется только для генерации сопроводительных писем.

Первый запуск действия по каждой площадке откроет браузер для одноразового входа (OAuth); дальше токен обновляется автоматически. Для Telegram вместо браузера — ввод номера телефона и кода в консоли при первом запуске поиска.
