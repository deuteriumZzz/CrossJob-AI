# Гайд по CrossJob-AI

**[📘 README](../README.md)** · **[📖 Этот гайд](GUIDE.md)**

Как настроить бота и что он делает на каждом шаге.

## Как это работает (цикл)

```
python main.py --auto headhunter   # или --auto superjob / --auto zarplata
  1. Берёт список позиций/ключевых слов из work_preferences.yaml (например "Python разработчик")
  2. Ищет вакансии по каждой позиции на выбранной площадке
  3. Отсеивает по чёрным спискам компаний/названий/локаций и фильтрам
     (опыт, тип занятости, дата публикации, remote/hybrid/onsite — для HH;
     для SuperJob пока только по ключевому слову + чёрные списки, см. "Ограничения")
  4. Для оставшихся вакансий:
     - подтягивает полное описание вакансии
     - подтягивает официальное описание компании-работодателя (тоже через API площадки)
     - LLM оценивает соответствие резюме вакансии от 1 до 10 (JOB_SUITABILITY_SCORE
       в config.py, по умолчанию порог 7) — ниже порога вакансия пропускается,
       письмо не пишется и отклик не отправляется
     - пишет сопроводительное письмо под конкретную вакансию + компанию,
       на основе текста из вашего resume.pdf (само резюме НЕ переписывается)
  5. Либо реально откликается (auto_apply: true), либо только показывает,
     что было бы отправлено (auto_apply: false — режим по умолчанию)
  6. Записывает каждый отклик в историю — JSON и читаемый HTML-отчёт
```

Поиск вакансий и анализ компании идут через официальные API площадок (`api.hh.ru`, `api.superjob.ru`) — не через скрейпинг страниц. Резюме на площадке (`resume_id`) используется как есть, отдельно от resume.pdf.

## Шаг 1. Резюме — куда класть и как проходит конвертация

Положите свой PDF-файл резюме как:

```
data_folder/resume.pdf
```

Никакой ручной конвертации делать не нужно — при каждом запуске бот сам читает текст из PDF (библиотека `pdfminer.six`, функция `extract_text`) и передаёт этот текст в LLM вместе с описанием вакансии и компании, чтобы написать сопроводительное письмо. Само содержимое `resume.pdf` никогда не переписывается и никуда не отправляется как новый файл — на HeadHunter вы откликаетесь тем резюме, которое уже загружено на вашем профиле hh.ru (см. `resume_id` ниже).

Язык письма определяется по языку самой вакансии, а не резюме — если ваше резюме на английском, а вакансия на hh.ru на русском, письмо всё равно уйдёт на русском (LLM получает явную инструкцию ориентироваться на текст вакансии, а не резюме). Это на случай, если резюме и площадка на разных языках — чтобы отклик не выглядел нелепо.

Если `resume.pdf` не найден — бот остановится с понятной ошибкой перед тем, как что-либо искать/отправлять.

## Шаг 2. secrets.yaml

Скопируйте `data_folder_example/secrets.yaml` в `data_folder/secrets.yaml` и заполните:

```yaml
llm_api_key: 'ваш ключ модели'

headhunter:
  client_id: "..."
  client_secret: "..."

superjob:
  client_id: "..."
  client_secret: "..."

zarplata:
  client_id: "..."
  client_secret: "..."

telegram:
  api_id: "..."
  api_hash: "..."
```

`client_id`/`client_secret` для HH — https://dev.hh.ru/admin; для SuperJob — https://api.superjob.ru/register/; для Zarplata.ru — по тому же принципу, что и HH (zarplata.ru входит в HeadHunter Group и использует ту же схему приложений/OAuth), но у бота эта часть пока не проверена на реальном приложении — если вход не сработает с первого раза, скорее всего дело в этом. При регистрации приложения SuperJob redirect URI укажите ровно `https://www.superjob.ru`, для Zarplata.ru — `https://zarplata.ru` — бот сам считывает код авторизации из адресной строки браузера, отдельный сервер не нужен. Для HH подойдёт любой redirect URI.

`api_id`/`api_hash` для Telegram — https://my.telegram.org/apps, войдите под своим личным аккаунтом (не бот) и создайте приложение. Это ваш обычный аккаунт Telegram будет "листать" каналы, поэтому используйте номер, которым не жалко так пользоваться.

### Другой провайдер LLM вместо OpenAI

Проще всего — через дашборд: вкладка **Настройки → Провайдер LLM**,
карточка нужного провайдера (OpenAI/Groq/Gemini/DeepSeek/Ollama),
выбор модели из списка (бесплатные помечены отдельно, рекомендованная
для наших задач — короной 👑) и свой API-ключ для этого провайдера —
сохраняется в `secrets.yaml` в блок `llm_api_keys:` (у каждого
провайдера свой ключ, они не путаются при переключении) и
применяется сразу, без перезапуска.

**Рекомендация по умолчанию — Groq, `openai/gpt-oss-120b`.**
Бесплатно, быстрый инференс (собственное железо Groq, не GPU-облако),
и для наших задач (оценка вакансии 1-10, сопроводительное письмо,
ответы на вопросы анкеты LinkedIn — короткие структурированные
ответы, не многошаговые рассуждения) этого с запасом хватает. При
типичном объёме вызовов (оценка каждой найденной вакансии + письмо на
каждый отклик) платный провайдер за день ощутимо накапает по счёту —
Groq снимает этот вопрос вообще. Запасной вариант, если упрётесь в
лимиты бесплатного тира Groq — Gemini `gemini-2.5-flash` (тоже
бесплатно, отдельный лимит).

Список моделей в дашборде (`PROVIDER_MODELS` в
`src/job_sources/llm_provider.py`) — не живой API-каталог, а
захардкоженный список, сверенный вручную; провайдеры (особенно Groq)
периодически снимают старые модели с бесплатного тира без долгого
уведомления. Если провайдер вернёт ошибку вида "model not found" —
это первое место, которое стоит проверить и обновить.

Тот же результат вручную — правкой `config.py`:

```python
LLM_MODEL_TYPE = "groq"       # openai (по умолчанию) | groq | gemini | deepseek | ollama
LLM_MODEL = "openai/gpt-oss-120b"  # оставьте пустым для дефолтной модели провайдера
LLM_API_URL = ""              # base_url — нужен только для ollama (например http://localhost:11434)
```

и в `secrets.yaml`:

```yaml
llm_api_keys:
  groq: 'ваш ключ Groq'
```

(старый одиночный `llm_api_key` по-прежнему работает как ключ по
умолчанию для `LLM_MODEL_TYPE` — но только для него; для любого
другого провайдера нужен именно свой ключ в `llm_api_keys:`, иначе
бот остановится с понятной ошибкой вместо того, чтобы тихо отправить
чужой ключ не туда). Для `ollama` ключ не нужен вообще — можно
оставить его пустым/не задавать. Устанавливайте только тот пакет из
requirements.txt, который реально используете
(`langchain-groq`/`langchain-google-genai`/`langchain-ollama`) —
остальные два можно не ставить.

### Уведомления в Telegram (опционально)

Добавьте в `secrets.yaml` блок `notifications` с токеном обычного
Telegram-бота (через @BotFather, не тот же аккаунт, что для чтения
каналов) и вашим `chat_id` — бот пришлёт сводку по завершении
прогона, при достижении дневного лимита откликов на площадке и при
новом ответе работодателя (`Check *replies`). Без этого блока бот
просто не отправляет уведомления, остальной функционал не меняется.

## Шаг 3. work_preferences.yaml

Скопируйте `data_folder_example/work_preferences.yaml` в `data_folder/work_preferences.yaml`. Ключевое:

```yaml
positions:
  - Python разработчик
  - Backend developer

locations:
  - Москва

company_blacklist:
  - имя_компании_которую_не_хотим

headhunter:
  auto_apply: false          # true — реально откликаться, false — только показать
  resume_id: "ваш resume_id с hh.ru"

superjob:
  auto_apply: false
  resume_id: "ваш resume_id с superjob.ru"

zarplata:
  auto_apply: false
  resume_id: "ваш resume_id с zarplata.ru"

telegram:
  channels:
    - some_public_job_channel   # username канала без @, как в ссылке t.me/username
  messages_per_channel: 100
```

`positions` — это и есть "ключевые слова": можно указать одну позицию или несколько, бот пройдётся по каждой (общий список работает для всех площадок сразу, включая Telegram — отдельного списка ключевых слов для него нет). Если оставить `positions: []` пустым — бот перед первым поиском сам прочитает `resume.pdf` и подберёт 2-4 подходящие должности через LLM (лог покажет, что именно подобрал — можно вернуться и прописать вручную, если не понравилось). `resume_id` для HH берётся из вашего профиля на hh.ru (открыть резюме → номер после `/resume/` в адресной строке), для SuperJob/Zarplata.ru — аналогично на соответствующем сайте.

Если оставить `resume_id` пустым, а `auto_apply: true` — бот не остановится сразу с ошибкой, а сам спросит у площадки список резюме, уже загруженных на вашем профиле: найдёт одно — использует его (в логе будет видно, какое именно), найдёт несколько — остановится и подскажет их id, чтобы вписать нужный, не найдёт ни одного — попросит сначала загрузить резюме на сайте площадки вручную. Локальный `resume.pdf` в сам отклик подставить нельзя — у официальных API HH/SuperJob/Zarplata нет способа "откликнуться файлом", только по id уже существующего на площадке резюме; `resume.pdf` при этом всё равно используется — для оценки вакансии и текста сопроводительного письма, независимо от `resume_id`.

`telegram.channels` — это username и каналов, и групп/супергрупп (Telethon читает историю сообщений одинаково для всех типов), просто перечислите нужные.

## Шаг 4. Первый запуск

```bash
pip install -r requirements.txt
python main.py
```

Выберите в меню **"Search & Apply on HeadHunter"**, **"Search & Apply on SuperJob"** или **"Search & Apply on Zarplata.ru"**. При первом запуске каждой площадки откроется браузер — войдите в свой аккаунт один раз, дальше вход будет проходить автоматически (токен обновляется сам).

Пока `auto_apply: false` — бот только покажет в логе, куда бы откликнулся и какое письмо бы отправил. Проверьте несколько писем, и только потом включайте `auto_apply: true` в `work_preferences.yaml`.

**geekjob.ru и rabota.ru — отдельный случай.** У обеих площадок нет официального API, поэтому поиск и парсинг вакансии идут напрямую по HTML-страницам сайта — это работает надёжно (страницы серверные, не JS; у rabota.ru даже стандартная schema.org-микроразметка). А вот сама кнопка отклика на обеих площадках требует входа в аккаунт и рендерится через JS/скрыта в статичном HTML — я не смог увидеть реальный механизм отправки без залогиненной сессии, а писать код по угадыванию — плохая идея, может тихо сломаться или отправить не то. Поэтому пункты **"Search on geekjob.ru (manual apply)"** и **"Search on rabota.ru (manual apply)"** только находят подходящие вакансии и пишут для каждой сопроводительное письмо (кладут в историю откликов как `dry_run`) — откликаться нужно вручную, скопировав готовое письмо. Автоотклик появится, когда будет с чем свериться вживую.

**Telegram — тоже только поиск, но по другой причине.** Вакансии в Telegram-каналах — это просто посты; откликаются на них обычно личным сообщением автору поста, а не через API. Бот забирает последние сообщения из каналов, перечисленных в `telegram.channels`, оставляет только те, что содержат хотя бы одно из ваших `positions`, и пишет для каждого сопроводительный текст (кладёт как `dry_run` — писать нужно вручную). При первом запуске пункта **"Search Telegram channels (manual reply)"** в консоли попросит ввести номер телефона и код из Telegram (плюс пароль, если включена двухфакторка) — это одноразово, дальше сессия сохраняется в `data_folder/output/.telegram_session`.

**GetMatch — тоже только поиск.** Сайт — SPA на Next.js, вакансий в исходном HTML нет вообще (проверено прямым запросом), поэтому бот открывает реальный Selenium-браузер, ждёт, пока страница дорендерится, и уже потом парсит. Кнопка "Откликнуться" на GetMatch — это мастер из 5 шагов (первый шаг — просто выбор формата работы), почти наверняка требующий логина на одном из следующих — не стал угадывать остальные шаги вслепую, поэтому **"Search on GetMatch (manual apply)"** тоже только ищет и готовит письмо.

**LinkedIn — самое рискованное и наименее проверенное.** У меня не было живого LinkedIn-аккаунта, чтобы залогиниться и свериться с реальной формой Easy Apply (в отличие от HH, где я сверялся с официальным API). Код опирается на хорошо задокументированные публичные паттерны разметки Easy Apply, но это best-effort, не подтверждённый вживую код — единственный такой во всём проекте. Поэтому:

- Используется `undetected-chromedriver` вместо обычного Selenium — LinkedIn активно вычисляет автоматизацию.
- Нужен `data_folder/job_application_profile.yaml` (пример в `data_folder_example/`) — отвечает на анкетные вопросы Easy Apply (авторизация на работу, готовность к переезду, ожидания по зарплате и т.д.) вместе с вашим `resume.pdf`.
- Если бот встречает незнакомый тип поля в анкете — пропускает вакансию целиком, не пытается угадать ответ.
- `auto_apply` в примере конфига — `false`, **и это специально так, несмотря на возможность включить сразу**: первый прогон — dry run, чтобы вы посмотрели, что бот сгенерировал в ответах на вопросы анкеты, прежде чем разрешать реальную отправку.
- Отдельный, более консервативный суточный лимит — `LINKEDIN_DAILY_APPLICATION_LIMIT` в `config.py` (по умолчанию 8, между вашими 5 и 10).
- LinkedIn **не входит** в `--auto all`/"Search all sources" — самая рискованная площадка не должна попадать в общий прогон случайно, запускайте её отдельно и осознанно: `python main.py --auto linkedin`.
- При первом запуске откроется окно браузера для входа — если появится 2FA/капча, завершите её вручную в этом же окне, бот подождёт до 5 минут.

**Запуск всех источников разом — "Search all sources" в меню или `python main.py --auto all`.** По очереди прогоняет каждую площадку с паузой между ними (10-30с) — если одна упадёт (сайт лёг, токен протух), остальные всё равно отработают. LinkedIn в этот список не входит (см. выше).

## Шаг 5. Проверка истории откликов

Каждый отклик (реальный или dry-run) сразу пишется в `data_folder/output/applications.html` — открывается в любом браузере, таблица: дата / площадка / компания / вакансия (ссылка) / статус / сопроводительное письмо (раскрывается по клику). Это и есть "красивая" статистика, чтобы не гадать через неделю, куда и что вы отправляли.

Быстрый поиск по конкретной компании — в меню **"Show sent applications"**: спросит компанию/должность для поиска (или Enter — покажет всё) и напечатает в терминал, плюс подскажет путь до HTML-отчёта.

**"Check HeadHunter replies"** (или `--auto check_hh_replies`) — сверяет ваши реальные отклики на HH с текущим статусом отклика по данным самого HH (например, "приглашение", "отказ" и т.д. — как называет их сам HH), чтобы не заходить на сайт вручную и увидеть, ответил ли работодатель. Только читает статус — если ответ ведёт на внешний сайт с формой (как иногда бывает и в LinkedIn), это всё ещё нужно сделать вручную, бот такое не обрабатывает. То же самое для **"Check Zarplata replies"** (`--auto check_zp_replies`, тот же API, что у HH) и **"Check SuperJob replies"** (`--auto check_sj_replies`) — у SuperJob эндпоинт `/messages/` подтверждён по названию из официального клиента, но точные имена полей в ответе не проверены вживую, поэтому статус может показать "не найден в текущих откликах", даже если ответ реально есть — не панацея, но лучше, чем ничего.

## Автоматический запуск (cron)

```bash
python main.py --auto all          # все площадки по очереди, с паузами
# или по отдельности:
python main.py --auto headhunter
python main.py --auto superjob
python main.py --auto zarplata
python main.py --auto geekjob
python main.py --auto rabota_ru
python main.py --auto telegram
python main.py --auto getmatch
```

Пример cron-задачи (раз в 3 часа, все площадки одной командой):

```
0 */3 * * * cd /path/to/CrossJob-AI && .venv/bin/python main.py --auto all >> log/all.log 2>&1
```

Если нужна независимость (одна площадка упала — остальные не должны ждать её пауз), запускайте раздельными строками cron, как раньше — `--auto all` специально не прерывается на ошибке одной площадки, но всё равно идёт последовательно, а не параллельно.

Повторные запуски безопасны: уже просмотренные вакансии не дублируются (история откликов общая для всех площадок), а `JOB_MAX_APPLICATIONS` в `config.py` ограничивает число откликов за один прогон.

Для Telegram первый запуск `--auto telegram` должен быть выполнен вручную в терминале (нужно ввести код входа) — в cron его можно добавлять только после того, как `.telegram_session` уже создан.

## Встроенный планировщик (--daemon) вместо cron

Альтернатива внешнему cron — `python main.py --daemon`: процесс сам
решает, когда запускать каждую площадку, и работает в переднем плане,
пока его не остановят (Ctrl+C). Какие площадки крутятся и с какой
периодичностью — управляется двумя полями в блоке каждой площадки в
`work_preferences.yaml`:

```yaml
headhunter:
  auto_apply: false
  schedule_enabled: true   # по умолчанию false — демон её не трогает
  interval_hours: 3        # раз в сколько часов проверять эту площадку
```

Это поле можно добавить в блок ЛЮБОЙ площадки, включая те, у которых
своего блока ещё нет (`geekjob`, `rabota_ru`, `getmatch`) — просто
впишите блок с этими двумя полями. `--daemon` и `--auto` взаимно
исключают друг друга (нельзя указать оба сразу). Состояние (последний/
следующий запуск, статус, последняя ошибка на площадку) пишется в
`data_folder/output/.scheduler_state.json` — это то, что показывает
вкладка "Обзор" в десктоп-приложении (см. ниже).

## Десктоп-приложение (веб-дашборд в нативном окне)

Вместо голого CLI/cron есть окно с обзором площадок (статус, лимиты,
последний/следующий запуск), историей откликов, ответами
работодателей, аналитикой по пробелам в резюме и предложениями
чёрного списка, и формой настроек вместо ручной правки YAML.

Если `data_folder/` ещё не существует, дашборд сам покажет экран
первого запуска (тот же смысл, что у CLI-визарда из раздела
"Установка" в README) — кнопка создаёт data_folder из шаблона и
опционально сразу пишет `llm_api_key`; резюме (`resume.pdf`) кладётся
вручную, как описано ниже, а должности/локации/чёрные списки и
провайдер LLM (если не OpenAI) со своим ключом можно сразу заполнить
во вкладке Настройки, без ручной правки YAML (см. "Другой провайдер
LLM вместо OpenAI" выше и панель "Поиск" ниже).

Требует дополнительных зависимостей поверх `requirements.txt`:

```bash
pip install -r requirements-desktop.txt
python desktop_app.py
```

Технически это тот же локальный веб-сервер (`src/webui/api.py`,
FastAPI), что можно поднять и напрямую через `uvicorn
src.webui.api:app --reload` и открыть в обычном браузере — `desktop_app.py`
просто оборачивает его в нативное окно (`pywebview`) без вкладок
браузера. Сервер слушает только `127.0.0.1` — снаружи недоступен.

Кнопка "Запустить"/"Остановить" в шапке окна включает/выключает тот
же планировщик, что и `--daemon`, только в фоновом потоке процесса
приложения, а не как отдельный процесс.

На вкладке "Настройки" есть панель "Поиск" — должности (они же
ключевые слова для Telegram-каналов), локации и три чёрных списка
(компании/слова в названии/локации), каждое поле — список, одно
значение на строку. Кнопка "Сгенерировать должности из резюме" — тот
же LLM-вызов, что автовывод позиций на старте CLI при пустом
`positions:`, только по явному запросу и с записью результата сразу в
`work_preferences.yaml`; требует `resume.pdf` в `data_folder/`, иначе
вернёт понятную ошибку вместо падения. Как и остальные настройки —
текстовая правка одной строки/блока, не `yaml.safe_dump` всего файла,
комментарии в вашем `work_preferences.yaml` не теряются.

На вкладке "Настройки" есть панель "Лимиты откликов" — дневной лимит
для HH/SuperJob/Zarplata, отдельный дневной лимит для LinkedIn, и
общий лимит откликов за один прогон (на все площадки сразу). Значения
пишутся в блок `limits:` в `work_preferences.yaml` (та же
текстовая правка, что и остальные настройки — не трогает ваши
комментарии в файле) и применяются сразу, без перезапуска. Дефолты —
`config.py` (`DAILY_APPLICATION_LIMIT`/`LINKEDIN_DAILY_APPLICATION_LIMIT`/
`JOB_MAX_APPLICATIONS`), их же дашборд показывает, если `limits:` ещё
не задан. Панель прямо показывает предупреждение: чем выше лимиты,
тем заметнее активность похожа на бота — площадки не публикуют
официальных порогов, так что это всегда компромисс между скоростью
отклика и риском ограничения аккаунта; LinkedIn блокирует
автоматизацию агрессивнее остальных, держите его лимит ниже.

Лимит за один прогон можно дополнительно переопределить для
конкретной площадки — колонка "Откликов за прогон" в таблице ниже на
той же вкладке (по площадкам, где сейчас настройки расписания). Если
для площадки своё значение не задано — используется общий лимит из
панели "Лимиты откликов" выше. Хранится как `job_max_applications`
внутри блока самой площадки (`headhunter:`, `superjob:` и т.д.) в
`work_preferences.yaml`, тем же способом, что и `auto_apply`/
`interval_hours`.

В той же таблице — колонка "Resume ID": для HH/SuperJob/Zarplata это
ссылка на резюме, уже загруженное вами вручную на самой площадке (см.
"Шаг 3. work_preferences.yaml" выше, где объяснено, откуда его взять)
— бот его не создаёт и не переписывает, только передаёт при отклике. Для площадок без официального API отклика (geekjob,
rabota.ru, GetMatch, Telegram) и для LinkedIn (у него свой Easy Apply
через сгенерированный PDF, resume_id туда не подходит) поле просто
не используется — оставьте пустым.

На вкладке "Настройки" есть панель "Резюме и сопроводительное
письмо" — те же три действия, что раньше были доступны только в
консольном меню (`Generate Resume`, `Generate Resume Tailored for Job
Description`, `Generate Tailored Cover Letter for Job Description`):
выбираете стиль оформления, при необходимости вставляете ссылку на
вакансию (обязательна для двух последних — под конкретную вакансию)
и жмёте нужную кнопку. Рендер идёт через тот же Selenium, что и
раньше, поэтому может занять до минуты — готовый PDF появляется как
кнопка "Скачать PDF".

Там же — кнопка "Обновить из PDF": `plain_text_resume.yaml`
генерируется из `resume.pdf` один раз через LLM и дальше
переиспользуется без изменений, даже если вы замените `resume.pdf`
на новую версию. Эта кнопка форсирует пересборку из текущего
`resume.pdf`.

### Сборка в exe (macOS и Windows)

```bash
pip install -r requirements-desktop.txt
pyinstaller desktop_app.spec
```

PyInstaller не кросс-компилирует — команду нужно запускать НА каждой
целевой ОС отдельно (собрать Windows-exe с Mac нельзя, и наоборот).
Результат в `dist/`:

- **macOS**: `dist/CrossJob-AI.app` — обычное приложение, двойной клик
  запускает; там же остаётся и `dist/CrossJob-AI/CrossJob-AI` (голый
  Unix-бинарник, если нужно запускать из терминала).
- **Windows**: `dist/CrossJob-AI/CrossJob-AI.exe`.

Оба варианта — one-dir, не один файл (так надёжнее работает Selenium/
webdriver-manager внутри). Готовый exe/app не подписан — Windows
покажет "Windows защитила ваш компьютер" (SmartScreen), macOS —
"неопознанный разработчик"; это ожидаемо для локального инструмента
без code signing. На macOS: System Settings → Privacy & Security →
"Открыть все равно". На Windows: "Подробнее" → "Выполнить в любом
случае" в окне SmartScreen. На каждой ОС ещё нужен установленный
Chrome — сам браузер PyInstaller не бандлит, только код бота.

На вкладке "Настройки" есть панель "Расходы на LLM" — суммарные
токены (и оценочная $-стоимость, только для нескольких известных
моделей OpenAI — для остальных провайдеров/моделей показываются
только токены без оценки в $) за сегодня и за всё время. Данные
пишутся в `data_folder/output/.llm_usage.json`, независимо от
провайдера (`config.LLM_MODEL_TYPE`).

Если демон/`--auto` упадёт на каком-то источнике (блокировка
площадки, сбой Selenium, ошибка LLM) — в дополнение к записи в лог
придёт уведомление в Telegram (если настроен, см. выше), чтобы не
узнавать об этом только по факту проверки логов вручную.

## Автоответ на сообщения работодателя (HeadHunter)

`headhunter.auto_reply: true` в `work_preferences.yaml` включает
автоматический ответ на сообщения работодателя в переписке по
вакансии (вопросы про зарплату, формат работы и т.п.) — LLM отвечает
на основе `resume.pdf`, вашего резюме на hh.ru (по `resume_id`),
`work_preferences.yaml` (`salary_expectations`, формат работы,
локации) и, опционально, публичного GitHub-профиля (`github:` в
`secrets.yaml`, только для технических вопросов). По умолчанию
выключено, как и все `auto_*`-флаги.

**НЕ проверено на живом аккаунте** — в отличие от поиска/отклика
(сверено с официальным API), чтение и отправка сообщений в треде
переговоров (`HeadHunterClient.list_negotiation_messages`/
`send_negotiation_message`) написаны по документированной схеме HH
API, но ни разу не вызывались вживую. Как и с Zarplata.ru — если
что-то не сработает при первом запуске, вероятнее всего именно тут.
Проверяйте вручную первые несколько ответов на hh.ru, прежде чем
доверять этому полностью.

**Не автоматизирует**: тесты/скрининг-анкеты (на самой HH или по
внешней ссылке) и переход по ссылкам куда-либо — только текстовые
сообщения в переписке.

## Ограничения текущей версии

- Реализованы HeadHunter, SuperJob, Zarplata.ru, LinkedIn (поиск + автоотклик), geekjob.ru, rabota.ru, GetMatch и Telegram-каналы (только поиск/уведомление). Хабр Карьера — в планах, ждёт вашей заявки на API (см. README).
- geekjob.ru, rabota.ru, GetMatch: автоотклик не реализован — механизм отправки отклика не был виден без живой залогиненной сессии (см. пояснение выше).
- LinkedIn: единственная площадка, чей код (Easy Apply) не сверен с живым аккаунтом — best-effort по известным паттернам, а не подтверждённая интеграция, как у остальных. Незнакомое поле анкеты — пропуск вакансии, не угадывание.
- Для SuperJob фильтры по опыту/типу занятости/дате публикации пока не отправляются в сам поиск (числовые коды API не подтверждены официально) — фильтрация идёт только по ключевому слову позиции и чёрным спискам. У HH все фильтры работают.
- Zarplata.ru: базовые URL API/OAuth выведены из документированного факта, что zarplata.ru — часть той же платформы HeadHunter Group, что и hh.ru (общий список разрешённых хостов в официальной документации), но не проверены вживую вызовом. Если при первом запуске что-то не сработает — вероятнее всего именно тут; остальная логика (фильтры, парсинг вакансии, отклик) идентична HH.
- "Анализ компании" — это официальное описание компании с самой площадки, не поиск по всему интернету.
