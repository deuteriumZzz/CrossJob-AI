## Как это работает (цикл)

```
python main.py --auto headhunter
  1. Берёт список позиций/ключевых слов из work_preferences.yaml (например "Python разработчик")
  2. Ищет вакансии по каждой позиции на выбранной площадке через браузерную сессию или официальный API
  3. Отсеивает по чёрным спискам компаний/названий/локаций и фильтрам
     (опыт, тип занятости, дата публикации, remote/hybrid/onsite)
  4. Для оставшихся вакансий:
     - подтягивает полное описание вакансии
     - подтягивает официальное описание компании-работодателя (с самой площадки)
     - LLM оценивает соответствие резюме вакансии от 1 до 10 (JOB_SUITABILITY_SCORE
       в config.py, по умолчанию порог 7) — ниже порога вакансия пропускается,
       письмо не пишется и отклик не отправляется
     - пишет сопроводительное письмо под конкретную вакансию + компанию,
       на основе текста из вашего resume.pdf (само резюме НЕ переписывается)
  5. Либо реально откликается (auto_apply: true), либо только показывает,
     что было бы отправлено (auto_apply: false — режим по умолчанию)
  6. Записывает каждый отклик в историю — JSON и читаемый HTML-отчёт
  7. Логирует воронку поиска: сколько найдено / уже видели / отсеялось
     по оценке / откликнулись / только просмотр, помогая понять почему
     дневной квота не набирается
```

**Архитектура:** все площадки, кроме Telegram, реализованы через браузерные сессии (Selenium + постоянные Chrome-профили для сохранения логина), а не через официальные API. Исключение — Telegram, который использует официальный Telethon API. Это значит:
- Вход — вручную один раз в браузере (пароль/SMS/код никогда не вводится ботом), дальше сессия хранится и переиспользуется.
- Селекторы и парсинг HTML страниц — это best-effort, если разметка сайта поменяется, может сломаться (но это касается только автоклика, поиск обычно надёжнее).
- Каждая площадка кодируется отдельно, в подпапке `src/job_sources/*/`.

Фильтрация по отдельным критериям зависит от того, что площадка отдаёт прямо в поиске: HeadHunter фильтрует по ключевому слову и `remote`/`hybrid`/`onsite` — фильтров по опыту/типу занятости/дате публикации в браузерном поиске сейчас нет (раньше они шли через официальный API HH, в текущей браузерной реализации не воспроизведены). Остальные площадки — просто парсят HTML списка после запроса и фильтруют в коде по ключевому слову и чёрным спискам.

## Шаг 1. Резюме — куда класть и как проходит конвертация

Положите свой PDF-файл резюме как:

```
data_folder/resume.pdf
```

Никакой ручной конвертации делать не нужно — при каждом запуске бот сам читает текст из PDF (библиотека `pdfminer.six`, функция `extract_text`) и передаёт этот текст в LLM вместе с описанием вакансии и компании, чтобы написать сопроводительное письмо. Само содержимое `resume.pdf` никогда не переписывается и никуда не отправляется как новый файл — откликаетесь вашим аккаунтом, который уже верификирован на площадке.

Язык письма определяется по языку самой вакансии, а не резюме — если ваше резюме на английском, а вакансия на hh.ru на русском, письмо всё равно уйдёт на русском (LLM получает явную инструкцию ориентироваться на текст вакансии, а не резюме). Это на случай, если резюме и площадка на разных языках — чтобы отклик не выглядел нелепо.

Если `resume.pdf` не найден — бот остановится с понятной ошибкой перед тем, как что-либо искать/отправлять.

## Шаг 2. secrets.yaml

Скопируйте `data_folder_example/secrets.yaml` в `data_folder/secrets.yaml` и заполните:

```yaml
llm_api_key: 'ваш ключ модели'

telegram:
  api_id: "..."
  api_hash: "..."

notifications:
  telegram_bot_token: "..."
  telegram_chat_id: "..."

getmatch:
  email: "..."

linkedin:
  email: "..."
  password: "..."

github:
  username: ""
  token: ""
```

**HeadHunter, Хабр Карьера, GetMatch, Wellfound, Himalayas, geekjob — секретов не требуют** — вход не через официальный API, а через настоящую браузерную сессию: при первом запуске откроется окно Chrome, вы входите сами (по номеру телефона + SMS для HH, по SSO для Хабра, по коду из Telegram для GetMatch, вручную для остальных), дальше сессия хранится в постоянном профиле браузера и повторный вход не нужен, пока площадка сама не сбросит сессию.

`api_id`/`api_hash` для Telegram — https://my.telegram.org/apps, войдите под своим личным аккаунтом (не бот) и создайте приложение. Это ваш обычный аккаунт Telegram будет "листать" каналы, поэтому используйте номер, которым не жалко так пользоваться.

`getmatch.email` и `linkedin.email`/`password` — данные вашего аккаунта. GetMatch логинится кодом из Telegram (вы видите форму входа в браузере), LinkedIn — обычной парой email/пароль, не через соцсети.

### Другой провайдер LLM вместо OpenAI

Проще всего — через дашборд: вкладка **Настройки → Провайдер LLM**,
карточка нужного провайдера, выбор модели из списка (бесплатные помечены отдельно, рекомендованная для наших задач — короной 👑) и свой API-ключ для этого провайдера — сохраняется в `secrets.yaml` в блок `llm_api_keys:` и применяется сразу, без перезапуска.

Где взять ключ для каждого провайдера:

| Провайдер | Страница ключа | Примечание |
|---|---|---|
| OpenAI | https://platform.openai.com/api-keys | Платный |
| Groq | https://console.groq.com/keys | Бесплатно, рекомендуется |
| Gemini | https://aistudio.google.com/apikey | Бесплатный тир |
| DeepSeek | https://platform.deepseek.com/api_keys | Платный |
| NVIDIA NIM | https://build.nvidia.com | Войти → профиль → Settings → API Keys → Generate API Key |
| OpenRouter | https://openrouter.ai/keys | Бесплатные модели — с суффиксом `:free` |
| Mistral | https://console.mistral.ai/api-keys | Бесплатный тир на младших моделях |
| Cohere | https://dashboard.cohere.com/api-keys | Бесплатный trial-ключ, лимит по вызовам/месяц |
| Hugging Face | https://huggingface.co/settings/tokens | Кредитный бесплатный тир |
| Ollama Cloud | https://ollama.com/settings/keys | Отдельно от локального Ollama ниже |
| LLM7.io | https://token.llm7.io | Ввести email — токен придёт сразу, без пароля |
| Cloudflare Workers AI | https://dash.cloudflare.com/profile/api-tokens | Кроме ключа нужен ещё и свой `account_id` (виден в личном кабинете справа) — его вставляете отдельным полем "Base URL" в дашборде (карточка Cloudflare), в виде `https://api.cloudflare.com/client/v4/accounts/ВАШ_ACCOUNT_ID/ai/v1` |
| Vercel AI Gateway | https://vercel.com/docs/ai-gateway/authentication-and-byok/api-keys | Не классический бесплатный тир, а $5 кредитов, реально обновляющихся каждые 30 дней — пока не привяжете платную карту |
| Ollama (локально) | — | Ключ не нужен, см. ниже |

**Рекомендация по умолчанию — Groq, `openai/gpt-oss-120b`.**
Бесплатно, быстрый инференс (собственное железо Groq, не GPU-облако),
и для наших задач (оценка вакансии 1-10, сопроводительное письмо,
ответы на вопросы анкеты LinkedIn — короткие структурированные
ответы, не многошаговые рассуждения) этого с запасом хватает. При
типичном объёме вызовов (оценка каждой найденной вакансии + письмо на
каждый отклик) платный провайдер за день ощутимо накапает по счёту —
Groq снимает этот вопрос вообще.

Список моделей в дашборде (`PROVIDER_MODELS` в
`src/job_sources/llm_provider.py`) — не живой API-каталог, а
захардкоженный список, сверенный вручную; провайдеры (особенно Groq)
периодически снимают старые модели с бесплатного тира без долгого
уведомления. Если провайдер вернёт ошибку вида "model not found" —
это первое место, которое стоит проверить и обновить.

Тот же результат вручную — правкой `config.py`:

```python
LLM_MODEL_TYPE = "groq"       # openai (по умолчанию) | groq | gemini | deepseek | ollama
LLM_MODEL = "openai/gpt-oss-120b"  # оставьте пустым для дефолтной модели провайдера
LLM_API_URL = ""              # base_url — нужен только для ollama (например http://localhost:11434)
```

и в `secrets.yaml`:

```yaml
llm_api_keys:
  groq: 'ваш ключ Groq'
```

(старый одиночный `llm_api_key` по-прежнему работает как ключ по
умолчанию для `LLM_MODEL_TYPE` — но только для него; для любого
другого провайдера нужен именно свой ключ в `llm_api_keys:`, иначе
бот остановится с понятной ошибкой вместо того, чтобы тихо отправить
чужой ключ не туда). Для `ollama` ключ не нужен вообще — можно
оставить его пустым/не задавать. Устанавливайте только тот пакет из
requirements.txt, который реально используете
(`langchain-groq`/`langchain-google-genai`/`langchain-ollama`) —
остальные два можно не ставить.

### Уведомления в Telegram (опционально)

Добавьте в `secrets.yaml` блок `notifications` с токеном обычного
Telegram-бота (через @BotFather, не тот же аккаунт, что для чтения
каналов) и вашим `chat_id` — бот пришлёт сводку по завершении
прогона, при достижении дневного лимита откликов на площадке и при
новом ответе работодателя. Без этого блока бот просто не отправляет уведомления, остальной функционал не меняется.

Для HeadHunter этот же бот дополнительно используется, чтобы
подтверждать заполнение внешних анкет (Google Forms по ссылке из
чата с работодателем, см. «Автоответ на сообщения работодателя»
ниже) — без `notifications` эта часть тоже просто не работает
(анкета не читается и не заполняется, а вместо неё ничего не
приходит).

## Шаг 3. work_preferences.yaml

Скопируйте `data_folder_example/work_preferences.yaml` в `data_folder/work_preferences.yaml`. Ключевое:

```yaml
positions:
  - Python разработчик
  - Backend developer

locations:
  - Москва

company_blacklist:
  - имя_компании_которую_не_хотим

headhunter:
  auto_apply: false          # true — реально откликаться, false — только показать

telegram:
  channels:
    - some_public_job_channel   # username канала без @, как в ссылке t.me/username
  messages_per_channel: 100
```

`positions` — это и есть "ключевые слова": можно указать одну позицию или несколько, бот пройдётся по каждой (общий список работает для всех площадок сразу). Любую площадку можно переопределить точечно, не трогая общий список — впишите свой `positions:`/`locations:` внутрь блока конкретной площадки (`headhunter:`, `telegram:` и т.д.); пусто или не задано там — используется общий список сверху (см. `effective_list` в `src/job_sources/preferences.py`). Вкладка "Обзор" в дашборде показывает, что реально ищется по каждой площадке с учётом этого фолбэка. Если оставить `positions: []` пустым — бот перед первым поиском сам прочитает `resume.pdf` и подберёт 2-4 подходящие должности через LLM (лог покажет, что именно подобрал — можно вернуться и прописать вручную, если не понравилось).

`telegram.channels` — это username каналов, и групп/супергрупп (Telethon читает историю сообщений одинаково для всех типов), просто перечислите нужные. Принимает как username (`some_channel`), так и полные ссылки (`https://t.me/some_channel`).

## Шаг 4. Первый запуск

```bash
pip install -r requirements.txt
python main.py
```

Выберите в меню одну из площадок. Для HeadHunter при **каждом** прогоне откроется окно браузера, но входить вручную нужно только один раз: при первом запуске войдите по номеру телефона и коду из SMS — дальше сессия сохраняется в постоянном профиле Chrome и повторный вход не требуется. Для остальных площадок окно браузера откроется один раз при первом запуске с `auto_apply: true`, потом сессия держится через постоянный профиль.

Пока `auto_apply: false` — бот только покажет в логе, куда бы откликнулся и какое письмо бы отправил. Проверьте несколько писем, и только потом включайте `auto_apply: true` в `work_preferences.yaml`.

**Описание каждой площадки при первом запуске:**

**HeadHunter** — браузерная сессия, вход по номеру телефона + SMS. Поиск идёт по всей России без фильтра по городу (вы работаете удалённо, конкретный регион не нужен). При `auto_apply: true` откликается кликом, при `auto_apply: false` — только dry-run логирование. Сверено на живом аккаунте.

**geekjob.ru** — браузерная сессия, вход только через OAuth соцсетей (Google/VK/GitHub/Yandex). Автоотклик — best-effort, не сверен с живым залогиненным аккаунтом: если кнопка "Откликнуться" не найдётся — тихо считается dry-run, ничего не падает. Включайте `auto_apply: true` только после проверки дважды на паре вакансий.

**Telegram** — поиск через личный аккаунт и официальный API (Telethon). Вакансии в Telegram-каналах — это просто посты. Берёт последние сообщения из каналов, отбрасывает те, что старше `telegram.max_post_age_days` (по умолчанию 7), оставляет те, что содержат хотя бы одно из ваших `positions`, и пишет сопроводительный текст. Если `telegram.auto_message: true` и в посте нашёлся ровно один `@username`-контакт — бот сам пишет ему короткое приветствие (`telegram.intro_message_template`, не всё письмо целиком — чтобы не выглядеть рассылкой), с человекоподобной паузой (2-10 минут), дневным лимитом (`telegram.daily_message_limit`) и окном активных часов (`telegram.active_hours_start/end`). При первом запуске попросит ввести номер телефона и код из Telegram (плюс пароль, если включена двухфакторка) — это одноразово, дальше сессия сохраняется в `data_folder/output/.telegram_session`. Диалог с контактом виден на вкладке дашборда **"Telegram" → "Диалоги"**: там же можно отвечать вручную или удалить диалог целиком. Автоответа на входящие нет и не планируется.

**GetMatch** — браузерная сессия на Next.js-SPA, вход по коду из Telegram (не по паролю, только email требуется в `secrets.yaml`). Реальный Selenium-браузер рендерит страницу (вакансий в исходном HTML нет). При `auto_apply: true` кликает "Откликнуться" — для заполненного профиля это один клик, без формы под письмо (GetMatch его не запрашивает). Письмо от LLM пишется и попадает в историю, но на площадку не уходит. При первом запуске откроется окно браузера, введите код из Telegram вручную; дальше сессия держится через постоянный профиль (`data_folder/output/.chrome_profile_getmatch`).

**LinkedIn** — самая рискованная площадка. Браузерная сессия + `undetected-chromedriver` (LinkedIn активно вычисляет автоматизацию). Селекторы Easy Apply сверены на живой залогиненной сессии 2026-08-23 (реальная 5-шаговая форма: Contact info → Resume → Additional Questions → Work authorization → Review). Нераспознанное поле анкеты пропускает вакансию целиком, а не гадает. Поиск — только удалённые вакансии. Нужны два файла: `data_folder/resume.pdf` (или `data_folder/resume_linkedin.pdf` отдельно для англоязычного рынка) и `data_folder/job_application_profile.yaml` (отвечает на анкетные вопросы Easy Apply). Вход — целиком вручную: при первом запуске с `auto_apply: true` откроется окно браузера, введите email/пароль/2FA сами. **НЕ входите через кнопку "Войти через Google"** — этот попап в автоматизированном браузере почти всегда даёт пустой белый экран. Дальше сессия держится через постоянный профиль (`data_folder/output/.linkedin_profile`). **Отдельного поля под PDF сопроводительного письма в форме Easy Apply нет** — письмо только сохраняется в историю откликов, никуда не прикладывается. `auto_apply` в примере конфига — `false` по умолчанию: первый прогон — dry run, чтобы вы посмотрели сгенерированные ответы на вопросы анкеты, прежде чем разрешать реальную отправку. LinkedIn не входит в `--auto all`/"Search all sources" — самая рискованная площадка не должна попадать в общий прогон случайно.

**Хабр Карьера** — браузерная сессия, вход вручную через SSO Хабра (включая Google-вход). Для вошедшего пользователя "Откликнуться" — мгновенная отправка одним кликом, без формы и без письма (письмо только пишется и попадает в историю). Поиск идёт через свободный текстовый поиск (`?q=`). Сверено на живом аккаунте 2026-08-28. При первом запуске с `auto_apply: true` откроется окно браузера для входа; дальше сессия держится через постоянный профиль (`data_folder/output/.chrome_profile_habr_career`).

**Wellfound** — браузерная сессия, вход вручную. Поиск идёт по JSON-LD schema.org на страницах вакансий (сверено на живом запросе 2026-09-02). Позиции сопоставляются с ролевой таксономией Wellfound (например `/role/r/python-developer`) — не любая формулировка найдёт совпадение. Автоотклик — best-effort, не подтверждён на живом залогиненном аккаунте: кнопка "Apply Now" подтверждена анонимно (переход по `?autoOpenApplication=true`), но что происходит ПОСЛЕ входа, вживую не проверялось — если модалка всё ещё просит пароль (сессия не вошла), отклик тихо считается dry-run.

**Himalayas** — экспериментальная площадка. Браузерная сессия + `undetected-chromedriver` (как LinkedIn), потому что сайт отдаёт анти-бот интерстишл на `/jobs` и `/companies/...` даже для обычного браузера. Из-за этого разметку карточек и форму отклика не удалось сверить визуально — селекторы лучшее предположение, а не подтверждённый вживую код. Прежде чем включать `himalayas.auto_apply: true`, прогоните dry-run и проверьте в логе `Found N matching himalayas.app vacancies` — при `N = 0` разметка сайта разошлась с предположением, нужно поправить селекторы по факту.

**"Search all sources" в меню или `python main.py --auto all`** — по очереди прогоняет все площадки (кроме LinkedIn) с паузой между ними. LinkedIn не входит специально — самая рискованная площадка не должна попадать в общий прогон случайно.

## Шаг 5. Проверка истории откликов

Каждый отклик (реальный или dry-run) сразу пишется в `data_folder/output/applications.html` — открывается в любом браузере, таблица: дата / площадка / компания / вакансия (ссылка) / статус / сопроводительное письмо (раскрывается по клику). Это и есть "красивая" статистика, чтобы не гадать через неделю, куда и что вы отправляли.

Быстрый поиск по конкретной компании — в меню **"Show sent applications"**: спросит компанию/должность для поиска (или Enter — покажет всё) и напечатает в терминал, плюс подскажет путь до HTML-отчёта.

**"Check HeadHunter replies"** (или `--auto check_hh_replies`) — ничего не делает, если `headhunter.auto_reply` выключен (по умолчанию); если включён — открывает браузерную сессию hh.ru и обрабатывает новые сообщения в чатах (см. «Автоответ на сообщения работодателя» ниже).

После каждого прогона в лог пишется сводная строка по площадке вида `[headhunter] funnel: found=38 already_seen=31 low_fit=5 applied=2 dry_run=0` — сколько вакансий вообще нашли, сколько уже видели раньше (пропущено без обращения к LLM), сколько отсеял порог оценки, и сколько дошло до отклика/dry-run. Отдельной таблицы в дашборде для этого нет — строка видна во вкладке "Логи" (читает `log/app.log`, см. `LOG_TO_FILE` в `config.py`), в т.ч. отфильтрованная по конкретной площадке. Помогает быстро понять, почему на какой-то площадке дневная квота не набирается: нет новых вакансий, слишком строгий порог оценки, или превышен лимит на прогон.

## Автоматический запуск (cron)

```bash
python main.py --auto all          # все площадки по очереди, с паузами
# или по отдельности:
python main.py --auto headhunter
python main.py --auto geekjob
python main.py --auto getmatch
python main.py --auto telegram
python main.py --auto linkedin
python main.py --auto habr_career
python main.py --auto wellfound
python main.py --auto himalayas
# отдельные проверки чата/ответов — не входят в --auto all, у каждой
# свой смысл и своя периодичность:
python main.py --auto check_hh_replies
python main.py --auto check_telegram_replies
```

Пример cron-задачи (раз в 3 часа, все площадки одной командой):

```
0 */3 * * * cd /path/to/CrossJob-AI && .venv/bin/python main.py --auto all >> log/all.log 2>&1
```

Если нужна независимость (одна площадка упала — остальные не должны ждать её пауз), запускайте раздельными строками cron, как раньше — `--auto all` специально не прерывается на ошибке одной площадки, но всё равно идёт последовательно, а не параллельно.

Повторные запуски безопасны: уже просмотренные вакансии не дублируются (история откликов общая для всех площадок), а `JOB_MAX_APPLICATIONS` в `config.py` ограничивает число откликов за один прогон.

Для Telegram первый запуск `--auto telegram` должен быть выполнен вручную в терминале (нужно ввести код входа) — в cron его можно добавлять только после того, как `.telegram_session` уже создан.

## Встроенный планировщик (--daemon) вместо cron

Альтернатива внешнему cron — `python main.py --daemon`: процесс сам
решает, когда запускать каждую площадку, и работает в переднем плане,
пока его не остановят (Ctrl+C). Какие площадки крутятся и с какой
периодичностью — управляется двумя полями в блоке каждой площадки в
`work_preferences.yaml`:

```yaml
headhunter:
  auto_apply: false
  schedule_enabled: true   # по умолчанию false — демон её не трогает
  interval_hours: 3        # раз в сколько часов проверять эту площадку
```

Это поле можно добавить в блок ЛЮБОЙ площадки, включая те, у которых
своего блока ещё нет (`geekjob`, `getmatch`) — просто
впишите блок с этими двумя полями. `--daemon` и `--auto` взаимно
исключают друг друга (нельзя указать оба сразу). Состояние (последний/
следующий запуск, статус, последняя ошибка на площадку) пишется в
`data_folder/output/.scheduler_state.json` — это то, что показывает
вкладка "Обзор" в десктоп-приложении (см. ниже).

## Десктоп-приложение (веб-дашборд в нативном окне)

Вместо голого CLI/cron есть окно с обзором площадок (статус, лимиты,
последний/следующий запуск), историей откликов, ответами
работодателей, аналитикой по пробелам в резюме и предложениями
чёрного списка, и формой настроек вместо ручной правки YAML.

Если `data_folder/` ещё не существует, дашборд сам покажет экран
первого запуска (тот же смысл, что у CLI-визарда) — кнопка создаёт data_folder из шаблона и опционально сразу пишет `llm_api_key`; резюме (`resume.pdf`) кладётся
вручную, а должности/локации/чёрные списки и провайдер LLM со своим ключом можно сразу заполнить
во вкладке Настройки, без ручной правки YAML.

Требует дополнительных зависимостей поверх `requirements.txt`:

```bash
pip install -r requirements-desktop.txt
python desktop_app.py
```

Технически это тот же локальный веб-сервер (`src/webui/api.py`,
FastAPI), что можно поднять и напрямую через `uvicorn
src.webui.api:app --reload` и открыть в обычном браузере — `desktop_app.py`
просто оборачивает его в нативное окно (`pywebview`) без вкладок
браузера. Сервер слушает только `127.0.0.1` — снаружи недоступен.

Кнопка "Запустить"/"Остановить" в шапке окна включает/выключает тот
же планировщик, что и `--daemon`, только в фоновом потоке процесса
приложения, а не как отдельный процесс.

На вкладке "Настройки" есть панель "Поиск" — должности (они же
ключевые слова для Telegram-каналов), локации и три чёрных списка
(компании/слова в названии/локации), каждое поле — список, одно
значение на строку. Кнопка
"Сгенерировать должности из резюме" — тот же LLM-вызов, что автовывод
позиций на старте CLI при пустом `positions:`, только по явному
запросу и с записью результата сразу в `work_preferences.yaml`.

В таблице площадок на той же вкладке — колонка "Готовность": ✅, если
в `secrets.yaml` заполнено всё нужное для этой площадки (email/password у LinkedIn,
email у GetMatch, api_id/api_hash у Telegram), ⚠️ с подсказкой (при
наведении), каких именно полей не хватает — если нет. Площадки без официального API (geekjob, GetMatch, LinkedIn, Telegram) не требуют секретов в стартовой таблице (`secrets.yaml` заполняется при первом запуске с `auto_apply`) — у них всегда ✅. Это не проверка, что ключи *рабочие* (это выяснится только
при реальном запуске), а просто что все нужные поля не пустые.

На вкладке "Настройки" есть панель "Лимиты откликов" — дневной лимит
для каждой площадки, отдельный дневной лимит для LinkedIn, общий
лимит откликов за один прогон (на все площадки сразу), и отдельно
**общий дневной лимит на все площадки вместе**
(`limits.total_daily_application_limit`) — жёсткий потолок: как только
сегодня суммарно отправлено столько откликов, автооткликер
останавливается везде, даже если у отдельной площадки в таблице ниже
свой лимит ещё не исчерпан. Значения пишутся в блок `limits:` в
`work_preferences.yaml` и применяются сразу,
без перезапуска. Дефолты — `config.py`
(`DAILY_APPLICATION_LIMIT`/`LINKEDIN_DAILY_APPLICATION_LIMIT`/
`JOB_MAX_APPLICATIONS`).

Кнопка "🎲 Распределить по площадкам" берёт уже
заданный общий дневной лимит и раскидывает его по площадкам, у
которых включено расписание демона, случайными
долями — LinkedIn получает вдвое меньший вес (площадка агрессивнее банит).

На вкладке "Настройки" есть панель "Резюме и сопроводительное письмо" — генерация документов (резюме/резюме под вакансию/письмо) и аудит резюме через LLM.

На той же вкладке панель "Ожидания по зарплате" —
два отдельных поля: сумма в рублях/месяц для HH (используется LLM как
подсказка при автоответе) и диапазон в долларах/год для
LinkedIn (ответ на screening-вопросы Easy Apply) — разные рынки, разные валюты.

Также кнопка "Обновить из PDF": `plain_text_resume.yaml`
генерируется из `resume.pdf` один раз через LLM и дальше
переиспользуется без изменений. Эта кнопка форсирует пересборку из текущего
`resume.pdf`.

На вкладке "Настройки" есть панель "Расходы на LLM" — суммарные
токены (и оценочная $-стоимость, только для нескольких известных
моделей OpenAI — для остальных провайдеров/моделей показываются
только токены без оценки в $) за сегодня и за всё время. Если за весь прогон ни один
вызов LLM не прошёл успешно (признак исчерпанного бесплатного лимита у провайдера) — панель
показывает предупреждение, плюс уведомление в Telegram.

Если демон/`--auto` упадёт на каком-то источнике (блокировка
площадки, сбой Selenium, ошибка LLM) — в дополнение к записи в лог
придёт уведомление в Telegram (если настроен), чтобы не
узнавать об этом только по факту проверки логов вручную.

### Сборка в exe (macOS и Windows)

```bash
pip install -r requirements-desktop.txt "setuptools<81"
pyinstaller desktop_app.spec
```

`setuptools<81` — не опционально: начиная с setuptools 81 из
`pkg_resources` убрали `NullProvider`, а собственный runtime-hook
PyInstaller (`pyi_rth_pkgres`) на него рассчитывает — без более старой
версии собранный `.app`/`.exe` падает сразу при старте с
`AttributeError: module 'pkg_resources' has no attribute
'NullProvider'`. Проверено вживую 2026-09-03 —
лучше собирать в отдельном venv, чтобы не понижать setuptools во всём
остальном окружении.

PyInstaller не кросс-компилирует — команду нужно запускать НА каждой
целевой ОС отдельно (собрать Windows-exe с Mac нельзя, и наоборот).
Результат в `dist/`:

- **macOS**: `dist/CrossJob-AI.app` — обычное приложение, двойной клик
  запускает; там же остаётся и `dist/CrossJob-AI/CrossJob-AI` (голый
  Unix-бинарник, если нужно запускать из терминала).
- **Windows**: `dist/CrossJob-AI/CrossJob-AI.exe`.

Оба варианта — one-dir, не один файл (так надёжнее работает Selenium/
webdriver-manager внутри). Готовый exe/app не подписан — Windows
покажет "Windows защитила ваш компьютер" (SmartScreen), macOS —
"неопознанный разработчик"; это ожидаемо для локального инструмента
без code signing. На каждой ОС ещё нужен установленный Chrome — сам браузер PyInstaller не бандлит, только код бота.

### Как запустить упакованное приложение

**На macOS:**

1. Скачайте `CrossJob-AI-macOS.zip` с [GitHub Releases](https://github.com/deuteriumZzz/CrossJob-AI/releases) (или соберите сами — см. "Сборка в exe" выше).
2. Распакуйте архив — появится папка `CrossJob-AI.app`.
3. Откройте Finder, найдите `CrossJob-AI.app`, кликните правой кнопкой → "Открыть".
4. macOS покажет предупреждение "неопознанный разработчик" — это нормально для локального инструмента.
5. Нажмите "Открыть все равно" в окне System Settings → Privacy & Security (если оно не открыло само, откройте его и найдите там CrossJob-AI в списке заблокированных приложений).
6. Окно приложения откроется — это веб-дашборд в нативном окне macOS.
7. Если `data_folder/` ещё не существует, дашборд покажет экран первого запуска: заполните LLM-ключ, создайте папку.
8. Положите `resume.pdf` в `data_folder/` (вручную, через Finder).
9. Откройте вкладку "Настройки" → "Поиск", заполните должности и локации.
10. На вкладке "Настройки" → "Провайдер LLM" убедитесь, что выбран бесплатный провайдер (рекомендуется Groq с моделью `openai/gpt-oss-120b`), и введите ваш API-ключ.
11. На вкладке "Обзор" включите расписание (`schedule_enabled`) для нужных площадок, затем нажмите кнопку "Запустить" в шапке окна — она включает встроенный планировщик (тот же, что у `--daemon`).
12. При первом запуске площадки откроется отдельное окно Chrome для входа — введите данные вручную (номер телефона + SMS для HH, SSO для Хабра, код Telegram для GetMatch, обычный email/пароль для LinkedIn и т.д.).
13. Дальше дашборд будет работать автоматически по расписанию или по клику кнопки "Запустить".

**На Windows:**

1. Скачайте `CrossJob-AI-Windows.zip` с [GitHub Releases](https://github.com/deuteriumZzz/CrossJob-AI/releases) (или соберите сами).
2. Распакуйте архив — появится папка `CrossJob-AI`.
3. Откройте папку, найдите `CrossJob-AI.exe`, кликните правой кнопкой → "Запустить от имени администратора" (или просто двойной клик).
4. Windows покажет предупреждение SmartScreen "Windows защитила ваш компьютер" — это нормально.
5. Нажмите "Подробнее" → "Выполнить в любом случае".
6. Окно приложения откроется.
7. Следуйте шагам 7-13 из macOS-инструкции выше (идентично).

**Первый запуск (экран инициализации):**

Если `data_folder/` не существует, дашборд покажет экран первого запуска:
- Поле для LLM API-ключа (можно оставить пустым и добавить позже во вкладке Настройки).
- Кнопка "Создать data_folder" — создаст папку из шаблона.
- После создания нужно вручную положить `resume.pdf` (через Finder/Explorer) в `data_folder/`.

## Автоответ на сообщения работодателя (HeadHunter)

`headhunter.auto_reply: true` в `work_preferences.yaml` включает
автоматический ответ на сообщения работодателя в чате hh.ru через ту
же браузерную сессию, что и поиск/отклик (не через официальный API —
см. «Как это работает» выше про причину). Перед каждым ответом бот
сначала спрашивает LLM, требует ли сообщение реакции вообще:
статусные и автоматические сообщения HH (просмотрено, вакансия
закрыта и т.п.) молча помечаются прочитанными, без ответа — отвечает
только на реальные вопросы (зарплата, формат работы, мини-интервью
прямо в чате), на основе `resume.pdf`, `work_preferences.yaml`
(`salary_expectations`, формат работы, локации) и, опционально,
публичного GitHub-профиля (`github:` в `secrets.yaml`). По умолчанию
выключено, как и все `auto_*`-флаги.

**Best-effort** — разметка чата hh.ru (`browser_replies.py`) взята из
публично задокументированных паттернов, часть проверена на живом
аккаунте, часть — нет; если что-то не сработает при первом запуске,
проверяйте вручную первые несколько ответов, прежде чем доверять
этому полностью.

Часть вакансий переводит с кнопки "Откликнуться" не на модалку с
тестом на той же странице, а на отдельную страницу анкеты
(`/applicant/vacancy_response`) — бот распознаёт и такой вариант, отвечает той же эвристикой/LLM и жмёт
кнопку отправки только если действительно нашёл её по видимому тексту.

### Внешние анкеты (Google Forms) в чате

Если сообщение работодателя содержит ссылку на форму — бот **не
переходит по ней и не вводит данные без вашего участия**. Вместо
этого: открывает ссылку, читает вопросы (подтверждено на живой
Google-форме — работает для любой формы на docs.google.com/forms), готовит черновик
ответов через LLM по резюме и вакансии, и присылает его вам в
Telegram. Дальше — только по вашей команде в
ответ на это сообщение:

- `да <id>` — заполнить и отправить форму как есть.
- `заново <id>` — перегенерировать черновик заново.
- `правка <id> <номер вопроса> <новый ответ>` — поправить один
  конкретный ответ, не открывая форму самому.

Заполнение и нажатие "Отправить" на стороннем сайте происходит
только после команды `да` — это единственное место во всём проекте,
где бот жмёт submit не на hh.ru, и делает это исключительно по
вашему явному подтверждению.

## Ограничения текущей версии

- Реализованы HeadHunter, LinkedIn, GetMatch, geekjob.ru, Хабр Карьера (поиск + автоотклик), Telegram-каналы (поиск + опциональные автосообщения найденным в постах контактам, без автоответа на входящие), Wellfound (поиск подтверждён, автоотклик best-effort) и Himalayas (экспериментальная).
- LinkedIn, geekjob.ru: автоотклик — best-effort, не сверен с живым залогиненным аккаунтом (LinkedIn — по известным публичным паттернам разметки Easy Apply; geekjob.ru — вход только через OAuth, пароль или код пользователя здесь никогда не вводится). Незнакомое поле/ненайденная кнопка — пропуск вакансии как dry-run, не угадывание.
- HeadHunter: поиск и отклик (включая клик, сопроводительное письмо и подтверждение "You applied"/появление кнопки "Chat") сверены на живом аккаунте. Поиск идёт по всей России без фильтра по городу (кандидат работает удалённо).
- "Анализ компании" — это официальное описание компании с самой площадки, не поиск по всему интернету.
