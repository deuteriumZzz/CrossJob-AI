# План доработок фронтенда (визуальный аудит)

Составлено по итогам трёх независимых аудитов `src/webui/static/{index.html,style.css,app.js}`:
направление визуального дизайна (`ecc:frontend-design-direction`), консистентность
дизайн-системы (`ecc:design-system`), доступность (`ecc:a11y-architect`, WCAG 2.2).

Статус: все пункты (high/medium/low) выполнены. Оставшиеся открытые хвосты отмечены внутри пунктов явно (не как отдельные чекбоксы).

## High priority

- [x] **Эмодзи вместо иконок рядом с кастомным SVG-набором** — `index.html:168,171,174` (`📡`, `🇷🇺`,
  `🌍`) заменены на SVG-иконки в том же стиле, что и иконки табов настроек (stroke-width 1.6,
  currentColor); добавлен класс `.section-subheading-icon` в `style.css`. Остальные декоративные
  эмодзи в help-диалоге и кнопках оставлены осознанно — это часть голоса интерфейса, не иконки.
- [x] **Нет `--space-*` токенов отступов** — добавлены `--space-1..6` в `:root` (`style.css`).
  Повторяющийся паттерн `style="flex:1;min-width:220px"` (4 места в `index.html`) вынесен в класс
  `.flex-grow-field`. Полная миграция остальных ~100 литеральных paddings/margins не выполнена —
  токен-скейл заведён, точечная миграция остального переносится в отдельную задачу по мере правок.
- [x] **Хардкод hex-цветов мимо токенов** — добавлены токены `--on-accent` (текст на акцентной
  кнопке, было `#0b1520`/`#fff` в 6 местах, включая отдельный light-theme override, который теперь
  не нужен и удалён), `--accent-hover` (было `#8fc4ff`, для light-темы посчитан через
  `color-mix()` — раньше в light-теме hover кнопки был light-theme-неуместный светло-синий) и
  9 `--source-*` токенов для брендовых цветов площадок (`style.css:2062-2106` в старой нумерации).
- [x] **`--danger` — фантомный токен** — объявлен по-настоящему в `:root` (`#e5636b`). Попутно
  найден и исправлен реальный баг: то же имя `--danger`/`--danger-bg` использовалось в
  `.tg-channel-remove:hover` с *другими* хардкод-значениями (`#b42318`/`#fff0f0` — светло-розовый
  фон, который выглядел бы неуместно в тёмной теме); переведено на существующий `--err` +
  `color-mix()`, что заодно чинит несостыковку с тёмной темой.
- [x] **Модалки без ARIA-роли диалога** — `role="dialog" aria-modal="true" aria-labelledby`
  добавлены не только на 3 изначально указанных (`#confirm-overlay`, `#calendar-overlay`,
  `#platform-drawer`), но и на все остальные диалоги той же `.command-overlay`-семьи
  (`#command-overlay`, `#shortcuts-overlay`, `#cover-letter-overlay`, `#trainer-overlay`,
  `#resume-audit-overlay`) — они используют тот же `trapFocus`-паттерн и страдали тем же багом.
  Где не было `id` у заголовка — добавлен.
- [x] **`outline: none` без видимой альтернативы фокуса** — `.tag-input-field`/`.tag-input`,
  `.filters input`/`select` и `.command-palette input` теперь получают явный focus-ring
  (`box-shadow`/`border-color`) при фокусе, а не просто убирают outline.
- [x] **Табы настроек не размечены как tabs** — `nav#settings-jump` получил `role="tablist"`,
  все 11 кнопок — `role="tab" aria-selected aria-controls id="…-tab"`, соответствующие
  `.settings-pane` — `role="tabpanel" aria-labelledby="…-tab"`. `switchSettingsTab` (`app.js`)
  теперь синхронизирует `aria-selected` с классом `active`. Полная ARIA Authoring Practices
  клавиатурная навигация (roving tabindex, стрелки влево/вправо) не реализована — кнопки и так
  фокусируемы табом, это можно добавить отдельно, если понадобится.

## Medium priority — сделано

- [x] **`.btn-accent`** — рассмотрено: единственное использование («Скачать PDF» после успешной
  генерации) семантически отличается от primary/secondary (мягкий акцентный CTA для финального
  шага) — решение: оставить как есть, это не лишняя сущность.
- [x] **`border-radius`** — заведён `--radius-xs: 6px` для семейства мелких квадратных
  icon-кнопок (`kbd`, `.copy-btn`, `.source-card-actions button`), `.source-icon` (7px) и
  `.row-actions-menu button/a` (6px) переведены на `var(--radius-sm)`. Остальные «стрей»-значения
  (heatmap-cell 3px/12px, confetti 1px/7px, progress-bar 3-4px/6-10px, chat-bubble 12px) оставлены
  литералами осознанно — это пропорциональные радиусы для мелких/декоративных элементов, где
  панельный `--radius`/`--radius-sm` выглядел бы неуместно круглым.
- [x] **`box-shadow`** — добавлен токен `--shadow-float` (свой для каждой темы) и применён к двум
  буквально идентичным теням (`.toast`-подобный поп-ап и `.tour-tooltip`); `command-palette` и
  `drawer-panel` оставлены отдельными литералами — они сильнее/направленно другие, а не дубли.
  Все rgba-глоу на основе `--accent`/`--ok`/`--err` (badge pulse, source-card hover, status-dots,
  save-flash, card-glow-pulse, tour-highlight) переведены на `color-mix()` — попутно исправлен
  реальный баг: эти glow'ы были жёстко зашиты под RGB тёмной темы и в светлой теме светились
  тёмно-синим/зелёным вместо актуального светлотемного акцента.
- [x] **Инлайн-стили в `index.html`** — 4 `<input type="file" style="display:none">` переведены на
  нативный атрибут `hidden` (не трогают JS — ни один toggle не обращается к их `style.display`);
  6 мест `style="margin:0"`/`style="margin-top:0"` вынесены в классы `.m0`/`.mt0`. Остальные ~100
  инлайн-стилей (в основном управляемые из `app.js` через `el.style.display`) оставлены — их
  безопасная миграция требует синхронной правки каждого места переключения в JS, вне разумного
  объёма этой правки.
- [x] **Типографика `.panel h3`** — увеличен с 14.5px/650 до 17px/600 (между body-текстом ~13px и
  `.view-header h2` 20px/700 теперь чёткая ступень).
- [x] **`--muted-2` контраст** — пересчитан по формуле WCAG: dark `#5f6673`→`#7e8492` (было
  ~3.05:1 на `--panel`, стало ~4.78:1), light `#8a8f9e`→`#686d81` (было ~3.05:1, стало ~5.1:1 на
  белом/~4.5:1 на `--panel-2`). Используется в основном как текст (10 мест) — так что подняли
  яркость, а не ограничили декором.
- [x] **`aria-hidden` на декоративных SVG** — добавлен ко всем 45 инлайн-SVG в `index.html`
  (были у 14 из 45), где не было — все проверены: сидят либо рядом с текстовой подписью, либо
  внутри кнопки с собственным `aria-label`.
- [x] **`autocomplete="off"`** — добавлен на `tg-api-id`/`tg-api-hash`. `outreach-hunter` при
  проверке уже имел `autocomplete="off"` — находка аудита была неактуальна.
- [x] **`copyToClipboard` озвучивание** — добавлен скрытый `#sr-announcer` (`aria-live="polite"`,
  `.sr-only`), в который пишется «Скопировано» одновременно с визуальной сменой иконки.

## Low priority — сделано

- [x] **Badge-разметка из `app.js`** — проверены все места, где JS сам ставит класс badge
  (`daemon-badge`, аккаунт-статусы, `setResumeAuditBadge`). Найден реальный баг:
  `resumeAuditScoreClass()` возвращает `"ok"` для сильного совпадения, но CSS-класса `.badge.ok`
  не существовало вовсе — бейдж «Сильное совпадение» рендерился без цвета. Добавлен `.badge.ok`
  (симметрично `.badge.warn`/`.badge.err`).
- [x] **3 file-input `style="display:none"`** — это уже было исправлено попутно в medium-проходе
  (переведены на атрибут `hidden`), включая 4-е такое же место (`tgq-resume-file`).
- [x] **Дублирование `role="status"` + `aria-live="polite"`** — убран лишний `aria-live` с
  `#activity` и `#toast-container` (роль `status` уже подразумевает `aria-live="polite"`
  сама по себе); `aria-atomic="false"` на toast-контейнере оставлен — это осознанная кастомизация.
- [x] **`#ai-prompt`** — проверено: `<summary>` с заголовком «Где взять список компаний?» и шаги
  `<ol>` уже идут в разметке раньше `<textarea id="ai-prompt">` — порядок DOM корректен,
  правка не требовалась.
- [x] **Контраст `--ok/--warn/--err` на своих фонах** — посчитан по формуле WCAG: `.badge.ok`
  (4.39:1 в light), `.badge.warn` (4.47:1), `.badge.err` (3.90:1) и `.badge.on` (4.52:1, впритык)
  не проходили или были на грани 4.5:1 в светлой теме (в тёмной — всё ОК, 5.4–8.3:1). Добавлен
  `:root[data-theme="light"]` оверрайд на более слабую тонировку фона через `color-mix()` — тёмную
  тему не трогает, светлую поднимает выше порога с запасом.
- [x] **Возврат фокуса в overlay-сценариях** — прочитан весь путь: `trapFocus()` сохраняет
  `previouslyFocused` и восстанавливает его в `release()`; **все** пути закрытия (`hideOverlay()`
  для всех `.command-overlay`-диалогов и отдельный `closePlatformDrawer()` для drawer'а) вызывают
  `releaseFocusTrap()`. Проверено по всем 9 сценариям — багов не найдено, фокус возвращается
  корректно везде.

## Не требует действий (сильные стороны, отмечено, чтобы не переделывать зря)

- Тёмная тема + полноценная светлая перепалитровка (`style.css:27-42`), а не инверсия — качественное
  решение.
- Палитра `--ok/--warn/--err/--accent` осмысленная, не «фиолетовый AI-дефолт».
- Только 4 градиента во всём файле, все — для глубины, не декоративный шум.
- `--radius`/`--shadow` в целом применяются последовательно там, где выборочно проверено.
