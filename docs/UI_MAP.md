# Карта интерфейса: было → стало

Этап 1 плана нового интерфейса (`docs/PLAN.md`, раздел F). Здесь каждая функция, кнопка и настройка сегодняшнего веб-интерфейса (`src/webui/static/index.html`, `app.js`) и её место в новом виде из демо: https://claude.ai/artifact/57RUzwiiiN8vZACmec7eZ6.

Правило одно: ни одна функция не пропадает. Если элемент из демо не виден, а в коде он есть, он всё равно остаётся (помечено «в демо нет — сохраняем»). Если что-то убирается, рядом написано, чем оно заменяется (сводка — в разделе 12).

## Как читать

- **Ключ** — будущая метка `data-ui="<ключ>"` у элемента в новом интерфейсе. По ним тест проверяет, что ничего не потерялось (раздел 14).
- **Сейчас** — где элемент сегодня и его `id` или класс в коде.
- **Станет** — экран → блок. «Шторка» — панель справа. «Ещё» — раскрывающееся «Ещё настройки» внутри раздела или шторки, на один клик ниже.
- **Как**: `=` остаётся как есть (новый вид, то же место); `→` переезжает; `≈` заменяется равноценным (что именно — в «Станет»); `+` новое (раздел 11).

## 0. Разделы

В меню те же 6 разделов. Подвкладки остаются там, где их два вида одного и того же.

| Сейчас (`view-*`) | Станет |
|---|---|
| `overview` — Главная | Главная |
| `history` — Вакансии → Вакансии | Вакансии → Отклики |
| `logs` — Вакансии → Технические детали | Вакансии → Журнал бота |
| `replies` — Общение → Входящие | Общение (одно окно: список, разговор, карточка вакансии) |
| `telegram` — Общение → Telegram-парсер | Общение (диалоги в том же окне); вход в аккаунт — Настройки → Подключения; правила — Настройки → Telegram-парсер |
| `contacts` — Компании → База | Компании → База |
| `outreach` — Компании → Рассылки | Компании → Рассылка |
| `analytics` — Аналитика | Аналитика |
| `settings` — Настройки → Настройки | Настройки: 4 группы одним списком |
| `resume` — Настройки → Мои резюме | Настройки → Мои резюме (отдельная страница, краткий раздел в группе «Поиск») |

## 13. Решения по спорным местам

1. **Автоотправка в Telegram.** В демо один блок, в коде два движка: поиск по расписанию (`/api/settings/telegram`: `auto_message`, лимит, часы) и парсер в реальном времени (`/api/settings/telegram-watch`: `auto_message`, паузы, часы, лимит). Решение: один блок «Автоотправка», внутри два подписанных переключателя — поведение бота не меняется.
2. **«Скрыть диалог» или «Удалить диалог».** Оставляем «Удалить диалог» с подтверждением: так работает сейчас, история не теряется молча.
3. **Новое в Общении** (`talk.tg.posts`, `talk.ai-replies`, `talk.later`, `talk.rewrite`, `settings.tg.preview`) сделано после основных этапов, поверх существующих данных, без изменения их формата.
4. **«Промт письма — Изменить».** Полная замена промта сломала бы разбор ответа ИИ (тема и письмо отдельными полями). Решение: основа общая, «ваши правила» дописываются к ней (`direct.letter_instructions`).
5. **«Откликнуться всё равно».** Отдельного «откликнуться по ссылке» у площадок нет: отклик идёт тем же путём, что обычный, когда площадка снова видит вакансию — без оценки ИИ, с письмом и в пределах лимита. Шторка говорит об этом прямо.
6. **«Пауза на всё».** Стоит всё, что уходит от вашего имени: отклики, рассылка, автоотправка и очередь Telegram, чат HH. Входящие ответы HR и команды боту читаются — иначе вы бы пропустили приглашение, пока пауза.
7. **Данные пользователя.** Ни один существующий файл не меняет формат. Новое — только добавками: поля `feedback`, `apply_anyway` в записях журнала; файлы `.pause_all.json`, `.notifications_history.json`, `.night_posts.json`; у постов Telegram-парсера — статус (`status`: new, later, sent, hidden, blocked), `found_at` и `send_id` в самой записи `.watch_posts.json` (модель из ветки main, общая для бота и окна); ключи настроек `notify`, `llm.fallback_order`, `direct.letter_instructions`, `telegram.preview_before_send`, `telegram.night_to_morning`. Ручные резервные копии — в отдельных папках, дневные не вытесняют.
8. **Узкое окно.** Меню не встаёт над страницей, а становится колонкой значков слева (как свёрнутое); на телефоне строки решений и черновиков — в две строки.

## 14. Как проверяется

- У каждого элемента из разделов 1–9 в новом интерфейсе — метка `data-ui="<ключ>"` (в шаблонах `app.js` — то же в виде `ui: "<ключ>"`). Если два старых элемента слились в один (например, `home.cycle` и `settings.cycle` — теперь один «Постоянный цикл»), у него несколько ключей через пробел: `data-ui="settings.cycle home.cycle"`.
- `tests/test_ui_map.py` читает ключи из первого столбца таблиц в разделах карты, отмеченных «перенесён» в таблице «Статус переноса», и проверяет, что каждый ключ стоит в метке в `index.html` или `app.js`. Ключи не повторяются.
- Раздел 11 тест не проверяет. Когда элемент сделан, строка переносится в свой раздел.
- На каждом этапе — снимки экранов «было / стало» и прогон тестов (`docs/PLAN.md`, раздел F).
