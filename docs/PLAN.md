### D5. Единые фильтры поиска с адаптерами площадок (из другого чата)
**Идея:** один общий набор фильтров в интерфейсе, а каждая площадка переводит его на свой язык. Десяти отдельных настроек не нужно.

- **В интерфейсе** один блок «Фильтры поиска» с общими понятиями: формат работы (удалённо, гибрид, офис), уровень (junior, middle, senior, lead), «только с зарплатой», «только быстрый отклик».
- **В коде** у каждой площадки маленький адаптер, который превращает эти значения в параметры своего сайта. Примеры из того чата (нужно сверить с кодом перед реализацией): LinkedIn `f_WT=2` для «удалённо», GetMatch `l=remote`, Habr `remote=true`. У HH в нашем коде уже `work_format=REMOTE/HYBRID/ON_SITE` (подтверждено), не `schedule`.
- **Чего площадка не умеет**, она пропускает; в интерфейсе у неё напротив этого фильтра пометка «не поддерживается». Бот ничего не угадывает.
- **Остаётся отдельным** только своё у одной площадки (например, Easy Apply у LinkedIn).
- **Зашитое сейчас** становится значениями по умолчанию (поведение не меняется, пока вы сами не переключите): LinkedIn `f_AL=true` (только Easy Apply), `f_WT=2` (только удалённые), `sortBy=DD`, `geoId=92000000` при пустой локации.

**Что сейчас разбросано** (по разбору в том чате, часть ещё не сверена): в карточке площадки (GetMatch: удалённо и уровень; Habr: удалённо, Djinni: опыт в коде `experience_years`, поля в интерфейсе не найдено); у HH формат работы и «только с зарплатой» на общей вкладке поиска; у LinkedIn всё зашито. Общие для всех: должности, локации, чёрные списки, «пропускать удалёнку только из США / Европы». Wellfound, Himalayas, GeekJob, Avito, Djinni не разобраны построчно.

**Полная карта фильтров по всем площадкам:** `docs/FILTERS_COVERAGE.md`.

**Порядок:** сначала LinkedIn, HH, GetMatch, Habr, Djinni; остальные подключать после проверки, что они вообще поддерживают фильтры. Сначала разобрать фильтры каждой площадки по коду, затем общая схема и адаптеры, затем блок в интерфейсе.

## G. Полировка UI поверх текущего скелета (план от 2026-10-12)

**Цель:** интерфейс ощущается цельным готовым продуктом, при этом навигация, разделы, данные и сценарии пользователя остаются прежними. Улучшения добавляются в существующие компоненты; новые библиотеки и декоративные эффекты без практической пользы не добавляем.

**Правила движения и обратной связи**
- Реакция на наведение/нажатие: 100–160 мс; открытие меню и шторок: 180–260 мс. Короткие сдвиги, прозрачность и смена поверхности; без постоянных фоновых движений.
- Списки и показатели анимируются только при первом появлении или реальном изменении данных, не при каждом опросе API.
- Для простых реакций использовать CSS, для существующих сложных переходов — уже подключённый GSAP. Уважать `prefers-reduced-motion` и настройку «Анимации: выключить», включая эффекты, запущенные из JS.
- У каждого важного действия видны состояния: готово, выполняется, завершено, ошибка и восстановление. Дублирующий запуск во время выполнения блокируется.

**Этапы**
1. Инвентаризация `docs/UI_MAP.md`: пройти Главную, Вакансии, Общение, Компании, Рассылку, Резюме, Аналитику, Настройки, Журнал и все общие меню/шторки. Для каждого действия отметить мышь, клавиатуру, фокус, загрузку, отключённое состояние, успех и ошибку; отдельно отметить, что уже реализовано.
2. Общие элементы: довести реакции кнопок, иконок, полей, переключателей, чипов, меню, шторок и уведомлений до одного ритма. Индикатор срока показа уведомления — без движения при уменьшенной анимации.
3. Доступность и управление: сортировка таблиц, действия в строках, имена кнопок и полей, командная палитра, фокус в окнах и onboarding. Все сценарии должны работать мышью и клавиатурой; подсветка фокуса не заменяется цветом строки.
